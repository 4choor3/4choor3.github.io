A 股量化数据管道

陈鑫宇2026-09-092026-09-15

回测和信号依赖一份稳定的本地行情。公开数据接口大多限频，盘中临时拉一段历史要等，多次拉取的结果也不一致，所以这份数据落在自己手里：约 7315 支标的、1990 年至今的前复权 A 股日线，数据源 baostock。

数据落地

字段是 date/open/high/low/close/volume。前复权保证历史价格连续可比，跨年份拼接不会出现除权造成的断点。文件按代码命名，一个标的一个 CSV，存于 HPC 的 stock_data_qfq/ 目录，共 7000 多个文件。

生成环境是 Python 3.12，pandas 做清洗和拼接，回测接 backtrader 与 vectorbt。数据源选 baostock 的原因：免费、接口稳定、支持前复权。

更新机制

更新走两条链路，各解决一类问题：

  • 每天 22:00 由 cron 触发增量，只补最近缺失的交易日；
  • 每 7 天做一次全量覆盖，把 1990 年至今重新拉一遍，纠正增量过程中累积的复权误差和漏点。

增量靠「上一次最后交易日的后一天」续接，中断重启不会重拉全历史；两种模式写同一个目录，按文件名对齐。

下面是单只标的的可运行版本，依赖 baostock 和 pandas，装完直接跑就能拉到数据。正式版把 code 换成 7315 支的循环，其余不用动；传 last_date=None 或删掉本地 CSV 就走全量。

这段代码运行过：sh.600000 拉到 6508 行（1999-11-10 至 2026-09-15），文件 516K；紧接着再跑一次，输出「新增 0 行，共 6508 行」，落盘前按 date 去重，不会重复写入。

跑起来之后修过的三个问题

起点差一天。增量起点用了 last_date 本身，而不是它的后一天，最后一根 K 线每天被重复写一遍，拼接后索引重复。这个问题没有报错，靠下游对账发现：画图时最新收盘价与前一天的记录对不上。修复是起点显式加一天，落盘前按日期去重。

异常被吞掉。baostock 偶发超时，最初的 try/except 把异常吃掉，脚本以 0 退出，日志没有异常痕迹，数据断更没人知道。修复分两步：失败路径一律 exit(1)；脚本末尾加自检，把应更新的标的数和实际写入数比对，不一致就告警。

空返回当「已最新」。周末 cron 照常触发，baostock 返回空 DataFrame，旧逻辑把「空」当成「已最新」提前返回，下一个交易日反而缺数。修复是两步判断：非交易日先短路退出，空返回不落盘。

这三种情况各需要一条明确分支：异常、空返回、非交易日都不能走正常路径退出，正常退出码只代表数据真的写进去了。

日常维护

数据更新是全自动的：cron 每天拉增量、每周做全量，出问题靠末尾自检的告警发现。维护工作集中在脚本本身：补数据源缺失的标的、调整自检和重试逻辑。

这部分现在交给 agent：需求和边界写清楚，初版由它产出，后续改动也由它执行。管道是例外——挂 cron 之前主逻辑要自己过一遍，agent 的说明写得再顺，也要对着代码确认。一次性的杂务（批量改名、从 PDF 抽表、定位报错）不专门写脚本，直接交给 agent 跑完。

集群上的重算与回测：长任务用 tmux 保活，断网不影响；批量计算写成脚本用 sbatch 提交 SLURM。

策略面

信号以 MACD、KDJ、筹码分布为主，偶尔打板。持仓周期 7–14 天，交易频繁，对滑点和手续费敏感，回测里先把成本模型固定下来，再调信号。backtrader 承载策略逻辑，vectorbt 做参数扫描。
